Retrieval Pipelines

~ 35 min read

A RAG pipeline turns a user question into a grounded answer by retrieving relevant context before generation. The retrieval step is where most quality — and most bugs — live.

Mental model: retrieval is search with a budget. You have a token budget for context; spend it on the chunks most likely to contain the answer, ranked and de-duplicated.

How it works

Worked example: embed the query, search the vector index for the top-k nearest chunks, re-rank them, then pass the survivors plus the question to the model with a citation instruction.
Scale, cost & latency notes
  • Re-ranking adds a model call per query — cache aggressively at the query level.
  • Top-k too high burns context budget and dilutes the signal; start at k=5.

Common mistakes

  • Indexing whole documents instead of semantically-sized chunks.
  • Skipping de-duplication, so three near-identical chunks crowd out coverage.
