**Engineering Mastery** voice: dense, intermediate, written for engineers/PMs who can code a little and already ship LLM features. Assumes vocabulary. Concrete dollar/token figures, production framing ("what pages you at 3am"), senior-judgment angle. Second person, em-dashes, light wit.

**AI Foundations** voice (calibrate DOWN one level — it's the cheaper prereq for total beginners / non-engineers): same warm second-person voice and analogy-driven style, but:
- Define every term the first time it appears; never assume prior vocabulary.
- Prefer everyday analogies over production war stories.
- Keep code minimal/illustrative (a beginner course — `PATTERNS.code` can be a tiny snippet or pseudo-code, not a 40-line router).
- Keep the SAME field structure as Engineering Mastery (continuity), but `mistakes`/`flags`/`ask` should be framed for a beginner ("things people get wrong when they start") rather than org-audit questions.
- Accurate, never dumbed-down to the point of being wrong. No invented model capabilities; hedge speculation.

**How to apply:** When in doubt, match Engineering Mastery's STRUCTURE exactly and its TONE closely, but lower the assumed-knowledge bar. The two courses must feel like one coherent ladder — Foundations should make Mastery feel like "the obvious next step" (per courses.ts blurb).
